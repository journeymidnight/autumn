  Verdict: DONE_WITH_CONCERNS
    The collection window fix correctly eliminates busy-spinning (code quality improvement).
    However, it does NOT push throughput to 65k Tier B' gate. The fundamental bottleneck
    is the single P-log OS thread serializing all logStream appends. The collection window
    only helps amortize overhead; the overhead is dominated by the ~4ms append latency per
    batch (1 RPC round trip to stream layer), not wakeup or queue-drain cost.

    The 500µs default window is too aggressive for 256-thread workloads — it introduces
    floor latency that compresses throughput. For real deployment, AUTUMN_LF_COLLECT_MICROS=100
    or lower is recommended (matching prior 100µs sleep timing but now event-driven).

Main gaps:

  - Next path for Tier B': parallelize Phase 2 (log appends) OR split partitions.
  - Default window 500µs should be tuned down to 100µs for this workload.
