Task scope: F035 — Extent node WAL for small-write durability

Current summary:
  WAL fully implemented for the extent node. Small must_sync writes (≤2MB)
  now go through a WAL for lower latency: WAL is synced, extent file write
  happens in parallel without sync_all(). On startup, old WAL files are
  replayed into extent files before accepting new connections.

  Key changes:
  - crates/stream/src/wal.rs (new): Pebble/LevelDB-style 128KB block framing,
    9-byte CRC32C headers (FULL/FIRST/MIDDLE/LAST), async Wal via tokio mpsc,
    WalRecord encode/decode, replay_wal_files, should_use_wal(must_sync, len).
  - crates/stream/src/lib.rs: pub mod wal added.
  - crates/stream/Cargo.toml: crc32c.workspace = true added.
  - crates/stream/src/extent_node.rs:
      ExtentNodeConfig::wal_dir + with_wal_dir() builder;
      ExtentNode::wal: Option<Wal> field;
      new(): Wal::open() → replay_wal() → cleanup_old_wals();
      replay_wal(): writes each WAL record to extent file, advances len;
      append(): WAL path with tokio::join!(wal.write, file.write_at) when
        should_use_wal; falls back to direct sync for large writes.
  - crates/server/src/bin/extent_node.rs: WAL enabled at data_dir/wal.
  - crates/stream/tests/wal_recovery.rs (new): 3 integration tests.
