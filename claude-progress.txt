Task scope: F031 – Value log separation for large values

Current summary:
  Implemented WiscKey-style key-value separation in the Rust partition server.
  - ValuePointer struct: 16-byte LE encoding (extent_id:8, offset:4, len:4).
  - ValueLoc::ValueLog variant added to in-memory index.
  - VALUE_THROTTLE = 4KB: values > 4KB go to logStream, smaller values stay inline.
  - OP_VALUE_POINTER (0x80): flag bit OR'd with op=1 in SSTable records to mark pointer entries.
  - Write path: large values appended to logStream after WAL write; vp_extent_id/vp_offset (vhead) updated.
  - Read path: read_value_from_log fetches block from logStream via StreamClient.
  - Flush path (locked + async): ValueLog entries write 16-byte vp.encode() with OP_VALUE_POINTER op.
  - Compaction: op & 0x7F == 1 reads value-or-pointer bytes; pointer bytes carried through as-is; ValueLog kv entries not overwritten to Stream.
  - Recovery: vp_extent_id/vp_offset read from TableLocations proto; SST records with OP_VALUE_POINTER restore ValueLog locs with real value_len from vp.len; logStream replayed from vhead to recover unflushed large-value entries; WAL replay on top.
  - Proto: TableLocations.vp_extent_id/vp_offset added (fields 2/3, backward-compatible).
  - 4 unit tests (encode/decode roundtrip, flag constants) + 3 integration tests pass.
  - All 11 integration tests pass.
