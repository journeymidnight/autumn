Task scope: F033 – GC with discard tracking and extent punch

Current summary:
  Implemented GC for logStream extents with discard-map tracking.

  Changes:
  - sstable/format.rs: MetaBlock gains `discards: HashMap<u64, i64>` (extentID -> reclaimable bytes).
    Encoded as [count:u32][eid:u64][sz:i64]* after vp_offset. CRC32C covers discard data.
    Backward compatible: old SSTables (no discard data) decode with empty map.
  - sstable/builder.rs: SstBuilder gains `set_discards(HashMap<u64, i64>)`, embedded in MetaBlock at finish().
  - sstable/reader.rs: SstReader gains `discards: HashMap<u64, i64>`, loaded from MetaBlock on open.
  - stream/client.rs: New `get_extent_info(extent_id) -> Result<ExtentInfo>` public method.
  - lib.rs:
    - GcTask enum { Auto, Force { extent_ids } }
    - PartitionData gets gc_tx: mpsc::Sender<GcTask>
    - do_compact: initializes discard map from input tables' existing discards;
      accumulates VP entry discards when deduplicating/dropping; passes discards to last
      output SstBuilder; validates discards against current logStream extent list.
    - get_discards(readers) and valid_discard() helpers.
    - run_gc(server, part, extent_id, sealed_length): reads extent, finds live VP entries
      (current LSM version still points to this extent), re-writes them to logStream,
      then punches the extent.
    - background_gc_loop: periodic (30-60s) + on-demand; aggregates discards from SstReaders,
      skips last (active) extent, runs GC on extents with >40% discard ratio (MAX_GC_ONCE=3).
    - trigger_gc(part_id): sends GcTask::Auto to gc_tx.
    - open_partition: spawns background_gc_loop alongside flush and compact loops.

  Tests:
  - Unit test: discards_round_trip — set_discards + SstReader.discards round-trips correctly.
  - Integration test: f033_gc_reclaims_log_stream_extents — overwrites large values, compacts
    (builds discard maps), triggers GC, verifies all keys still return correct v2 values.
  - All 12 unit tests + 12 integration tests pass.
