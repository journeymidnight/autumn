Task scope: Bug fix — gRPC message size limits causing all puts to fail

Current summary:
  Fixed two related bugs that caused all put operations to fail:

  1. ExtentNode read_bytes/copy_extent sent entire extent payloads as single gRPC messages.
     SSTs > 4MB (tonic default) triggered OutOfRange errors during partition recovery.
     Fix: chunk streaming responses into 1MB pieces.
     Files: crates/stream/src/extent_node.rs
     Commit: 071b5364

  2. tonic defaults to 4MB max message size; Go uses 64MB (8MB for manager).
     PutRequest with large values and AppendRequest payloads both exceeded the limit.
     Fix: set max_decoding_message_size / max_encoding_message_size = 64MB on all
     ExtentNode and PartitionServer gRPC endpoints (8MB for manager), matching Go.
     Files: crates/partition-server/src/lib.rs, crates/stream/src/extent_node.rs,
            crates/stream/src/client.rs, crates/server/src/bin/autumn_client.rs,
            crates/manager/src/lib.rs
     Commit: 303b84fe
