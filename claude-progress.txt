Current summary:
  Branch: perf-r1-partition-scale-out (worktree /data/dongmao_dev/autumn-perf-r1)

  Removed the R3 `stream_states: DashMap<u64, Arc<Mutex<StreamAppendState>>>`
  Mutex-guarded per-stream state.  Replaced with ONE single-owner compio
  worker task per stream_id that owns the full `StreamAppendState` and a
  `FuturesUnordered` of in-flight 3-replica joins.  Public API talks to
  the worker via a bounded `mpsc<StreamSubmitMsg>` (cap=256) + per-op
  oneshot ack.

  Rationale: even R3's short lease/ack locks still serialize multiple
  concurrent callers of `append_payload_segments(stream_id, ...)`.  Step
  4.3 removes all locks around the state machine by making state
  single-owner — access is serialized by the actor pattern, not by a
  Mutex.  This unblocks step 4.4 (PS P-log concurrent submits into the
  stream worker).

  Architecture:
    crates/stream/src/client.rs
      • StreamClient constructor now uses Rc::new_cyclic so the struct
        stores Weak<StreamClient>; per-stream workers carry the weak
        ref in a WorkerRemovalGuard that cleans up `stream_workers`
        on exit — no Rc cycle, clean shutdown.
      • connect / new_with_revision return `Rc<StreamClient>` now.
        Public API methods still take `&self`, so callers' `sc.append()`
        works via Deref.  Partition-server's `Rc::new(new_with_revision(...))`
        simplified to just the constructor.
      • StreamSubmitMsg { Append{payload_parts, must_sync, revision,
        ack_tx}, ResetTail{tail}, SeedCursor{cursor}, Shutdown }
      • stream_worker_loop — true SQ/CQ (4.2 v3 pattern adapted):
          1. drain ready completions via `inflight.next().now_or_never()`
          2. branch on (n_inflight, at_cap):
               n_inflight == 0 → await submit_rx alone
               at_cap          → await inflight.next() alone (back-pressure)
               otherwise       → select(submit_rx.next, inflight.next())
                                 Left  (SQ wins) → apply message (Append
                                                 fires 3 send_vectored
                                                 sequentially, pushes the
                                                 3-replica join future
                                                 into FU, returns)
                                 Right (CQ wins) → apply_completion:
                                                 parse 3 frames, ack or
                                                 rewind/poison, send
                                                 AppendResult via ack_tx
      • Retry lives in the public API (Option A):
          for alloc_retry in 0..MAX_ALLOC_PER_APPEND (3):
            send Append, await ack
            Ok     → if end >= max_extent_size: alloc + ResetTail; return
            NotFnd → alloc + ResetTail; retry
            Locked → propagate immediately
            soft   → sleep 100ms, reload tail, ResetTail; retry (≤2×)
            hard   → alloc + ResetTail; retry
      • ensure_tail_initialised — per-stream futures::lock::Mutex<bool>
        serialises first-use so multiple concurrent first-callers don't
        each RPC the manager.  Sends ResetTail + SeedCursor (if
        commit_length > 0) to the worker before returning.
      • Preserved R3 state-machine semantics exactly:
          lease_cursor monotonic, ack advances commit over contiguous
          prefix via BTreeMap, rewind_or_poison on failure, poisoned
          flag on out-of-order failures, MAX_ALLOC_PER_APPEND=3,
          header.commit = lease-time cursor (Option A).

  New tests (tests/stream_sqcq.rs):
    1. concurrent_append_preserves_order_within_stream
       10 concurrent callers append to the same stream; sorted offsets
       must be contiguous, total bytes = N*PAYLOAD, commit_length
       matches.  Validates worker actor serialises lease() across
       concurrent public-API callers without gaps.
    2. worker_handles_back_pressure
       AUTUMN_STREAM_INFLIGHT_CAP=4, submit 100 concurrent ops.  All
       complete (no deadlock). Validates `at_cap` branch does CQ-only
       until slots free; callers parked on bounded send().await
       eventually progress.
    3. cq_advances_commit_on_out_of_order_completion
       30 concurrent small appends, joined via futures::join_all.
       Final commit_length == total bytes leased.  Validates BTreeMap
       prefix-advance under overlapping completion.
    4. sq_continues_submitting_while_cq_drains
       1000 concurrent vs sequential appends; assert concurrent ≥ 1.3×
       speedup.  Measured typical: 2.4× speedup.  Indirect proof that
       SQ and CQ overlap in the worker loop (would collapse to 1× if
       the worker were lease→fanout→await→ack sequentially per op).

Main gaps / concerns:
