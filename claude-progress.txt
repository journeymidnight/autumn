Task scope: Per-partition StreamClient + crash recovery bug fix

Current summary:
  Fixed two issues identified by benchmark regression (~39 ops/s) and adversarial review:

  1. Crash recovery bug (critical): open_partition only replayed logStream when
     recovered_vp_eid > 0. A partition that accepted writes but never flushed
     (no checkpoint) would silently lose all acked writes on restart.
     Fix: added "no-checkpoint" branch — when tables is empty and vp_eid == 0,
     replay from the very start of logStream (matching Go's `WithReadFromStart` path).

  2. Per-partition StreamClient (write perf regression):
     - Added StreamClient::new_with_revision() constructor that reuses an existing
       owner-lock revision without calling acquire_owner_lock again.
     - Added revision() / owner_key() accessors to StreamClient.
     - Added manager_endpoint: String to PartitionServer.
     - Added stream_client: Arc<Mutex<StreamClient>> to PartitionData.
     - open_partition creates a per-partition StreamClient from the server's revision.
     - All I/O in flush, compact, GC, write path now uses the partition's own client.
     - split_part coordination RPCs (commit_length, acquire_owner_lock,
       multi_modify_split) still use the server-level stream_client.

  3. Lock scope optimization in process_write_batch (Step 5):
     - Phase 1: hold write lock → validate, assign seqs, encode blocks, clone sc → release
     - Phase 2: do append_batch RPC without holding ANY partition lock
     - Phase 3: re-acquire write lock → insert memtable, update VP head, maybe_rotate
     Eliminates blocking reads/flushes/compaction during network I/O.

  4. Fixed integration test build: added must_sync: false to PutRequest initializers
     in crates/manager/tests/integration.rs (pre-existing breakage from prior commit).
