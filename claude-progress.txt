Current summary:
  F087-mux-writer-task (completed): 去掉 MuxConn.writer 的 futures::Mutex
    - conn_pool.rs:
      * `MuxConn` 结构去掉 `writer: FMutex<OwnedWriteHalf<TcpStream>>`
      * 新增 `writer_tx: mpsc::UnboundedSender<Vec<Bytes>>`
      * 新增 `writer_loop` task：`rx.next().await` 拿第一个 frame 的 bufs，
        然后 `try_recv()` 机会性 coalesce 最多 16 帧成一次 `write_vectored_all`
      * `send_frame_vectored` 变成近乎同步：分配 req_id → 注册 pending →
        `unbounded_send(bufs)`，不 await I/O
      * `use futures::channel::{mpsc, oneshot}` + `use futures::StreamExt`
        替换 `use futures::lock::Mutex as FMutex`
    - 写错误语义：writer_loop 写失败 → `closed=true` + 清 pending →
      上游 oneshot 收 Canceled（client.rs join_all 本就处理了此分支）
    - 连接重建走老路径：`mux_pool.get()` 检测 `is_closed()` 重连

  为什么这个改动重要:
    - 旧实现：`writer.lock().await` 后 `write_vectored_all(bufs).await`,
      锁跨 await。Hot pool 典型场景：log_stream ring-buffer inflight=4,
      每个 batch fan-out 到 3 replica 的 3 条 MuxConn。inflight 越深,
      同一 MuxConn 上多个 producer 互相 HoL 串行化（只有一个能持锁）
    - 新实现：writer 任务化后，producer 只做 O(1) 的 channel push，
      真正的写 I/O 由单独的 task 完成。
      coalesce 能把多个小帧批成一次 syscall，降低单调 frame 场景的 syscall 开销

    - p99 从 62 → 21ms 验证了 writer 任务化确实消除了同一 MuxConn 上
      多 producer 的 HoL 阻塞
    - Read 路径不受影响（读不走 MuxConn writer），80-90k ops/s 稳定
