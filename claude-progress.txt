Task scope: F099-J — collapse PS Dispatcher worker pool into the per-partition
  P-log thread. Thread-per-partition architecture: all I/O and state for a
  given partition happens on ONE OS thread. Accept OS thread unchanged; main
  compio thread forwards each accepted fd across a futures::channel::mpsc to
  the owning partition's P-log runtime. P-log's fd-drain task converts
  std::TcpStream -> compio::TcpStream and spawns handle_ps_connection on the
  SAME compio runtime that runs merged_partition_loop. ps-conn -> merged_loop
  handoff is now a same-thread PartitionRequest mpsc (no eventfd wake, no
  cross-thread futex). PartitionRouter DashMap deleted. N=1 fast path only;
  N>1 routing marked TODO(F099-K).

  Root cause of regression (anticipated by the task spec and confirmed):
    256 ps-conn tasks now share the P-log compio runtime. Each task does
    read(4 KB frame).await → req_tx.send.await → resp_rx.await → write(40 B
    frame).await per cycle. At 256 concurrent clients this drives P-log user
    CPU from ~57 % (F099-H measurement) to ~100 %. The merged_loop write
    pump's 4 ms batch RTT stalls slightly because it now competes with
    frame decoding + dispatch + response-encoding on the same thread.

    At low connection counts (Scenario B at 1 × d=64) there is no competing
    work, so F099-J neither helps nor hurts.

Main gaps:
  1. PERF REGRESSION at 256-client workload (primary harness). Cause: ps-conn
     + merged_loop collocation saturates P-log at 100 % CPU. Spec-predicted
     failure mode. No mitigation in scope for F099-J (would require
     introducing scheduler partitioning within a single compio runtime, or
     re-splitting ps-conn onto its own runtime — either of which defeats the
     same-thread motivation).
  2. N > 1 fd routing deferred to F099-K (TODO markers in lib.rs). Current
     code sends every fd to the first partition in the map; at N > 1
     misrouted requests reject with NotFound.
  3. --conn-threads is a harmless no-op (preserved for CLI compat) but could
     be removed entirely in a follow-up cleanup pass.
