Task scope: Performance optimization — eliminate redundant network RPCs

Current summary:
  Implemented 4 performance optimizations targeting unnecessary network round trips.
  All focused on caching: zero new RPCs on steady-state operations.

  1. Cache current_commit in StreamClient (crates/stream/src/client.rs):
     - Added commit_cache: HashMap<u64, u32> field (keyed by extent_id)
     - append_payload uses cached value instead of calling current_commit() RPC
     - First append to any extent still calls current_commit() (crash recovery safety)
     - Cache updated after every successful append with appended.end
     - Cache evicted on error, retry, saw_not_found, or extent rollover
     - Eliminates 1 commit_length RPC per append in steady state

  2. ClusterClient routing cache (crates/server/src/bin/autumn_client.rs):
     - Added regions: Vec<(u64, RegionInfo)> and ps_details: HashMap<u64, PsDetail>
     - connect() calls refresh_regions() once to populate cache at startup
     - resolve_key(): local lookup_key() with linear scan, refresh+retry on miss
     - resolve_part_id(): same pattern — local lookup, refresh on miss
     - all_partitions(): uses cache, no GetRegions RPC
     - refresh_regions() available for manual invalidation
     - Eliminates GetRegions() RPC on every put/get/del/head/ls/bench operation

  3. Cache extent_info in StreamClient (crates/stream/src/client.rs):
     - Added extent_info_cache: HashMap<u64, ExtentInfo> field
     - Added fetch_extent_info() helper: cache-first, populate on miss
     - read_bytes_from_extent() uses fetch_extent_info() instead of direct manager RPC
     - get_extent_info() delegates to fetch_extent_info()
     - On read error: invalidates cache entry for that extent_id
     - Eliminates extent_info manager RPC on every VP (large value) read

  4. Remove manager RPC from ExtentNode read_bytes (crates/stream/src/extent_node.rs):
     - Removed extent_info_from_manager() call from read_bytes handler
     - Uses local ExtentEntry state (eversion atomic) for eversion checks
     - Seal state is maintained by append path and re_avali RPC — no polling needed
     - Aligns with Go's extent node which never calls the manager on reads
     - Eliminates 1 manager RPC per VP read on the server side
