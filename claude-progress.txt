Task scope: F061 FUSE filesystem — 修 readdir segfault + flush 丢 size 两个阻塞 bug，通过手工集成测试

Current summary:
  三处修改:
    1. crates/fuse/src/state.rs: `kv_range` 重命名为 `kv_range_keys`，返回 `Vec<Vec<u8>>`
       - 背景: PS `handle_range` 默认只回 key，`RangeEntry.value = vec![]`，这是有意的 wire contract
       - 原来 FUSE 以为 range 返回 (key, value) 对，直接 decode 空 bytes 就走 rkyv `from_bytes_unchecked`
         读未初始化内存 → segfault
    2. crates/fuse/src/dir.rs: readdir 先 `kv_range_keys` 拿 dirent key 列表，再对每个 key `kv_get`
       取 DirentValue；rmdir 只用 keys 判空不再解 value
    3. crates/fuse/src/schema.rs: `decode_dirent` / `decode_inode_meta` 遇到空 bytes 提前返回 Err，
       防止上游漏过空 value 时再次触发 rkyv unchecked segfault
    4. crates/fuse/src/write.rs: `flush_inode` 重构
       - 原来当写缓冲已空（chunks 已在 write() 路径增量刷写）时直接 return，不调用 put_inode
       - 结果：cp 2MB 文件后 md5 正确，但 umount+remount 后 size=0、内容空
       - 修复：buffer 为空也继续往下走，dirty 位已置则 put_inode 持久化 size/mtime

  手工集成验证（/tmp/autumn-fuse-mnt，对 1× local cluster）：
    - mkdir / rmdir / rmdir-non-empty(ENOTEMPTY)
    - create small (inline)、cat 读回一致

    - 嵌套目录 a/b/c、find tree 正确
    - rename 文件 / 重命名目录
    - rm -rf 递归删除
    - umount + remount 后文件内容 md5 仍然一致（持久化闭环）
