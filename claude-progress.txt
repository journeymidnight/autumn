Task scope: F032 – SSTable bloom filter, prefix compression, block-based format, remove BTreeMap

Current summary:
  Implemented block-based SSTable format, replacing the old flat-record format and
  the in-memory BTreeMap key index entirely.

  New sstable module (autumn-rs/crates/partition-server/src/sstable/):
  - format.rs: EntryHeader, BlockOffset, MetaBlock (with CRC32C), DecodedBlock (prefix decompression)
  - bloom.rs: BloomFilter + BloomFilterBuilder (xxh3, 1% FPR, double-hashing)
  - builder.rs: SstBuilder (block-based SST construction with prefix compression, 64KB/1000 entry blocks)
  - reader.rs: SstReader (opens from Arc<Vec<u8>>, parses MetaBlock, reads/verifies blocks)
  - iterator.rs: BlockIterator, TableIterator, MergeIterator, MemtableIterator
  - mod.rs: re-exports

  lib.rs complete rewrite:
  - Removed: BTreeMap kv, ValueLoc enum, KeyMeta struct, sst_cache HashMap,
    apply_sst_locs_stream, apply_record_meta, decode_record_metas, read_from_loc
  - New MemEntry { op, value, expires_at } stored directly in SkipMap
  - Get/Head: lookup_in_memtable + lookup_in_sst (bloom check + block scan) newest-first
  - Range: MergeIterator over TableIterators + MemtableIterator with user-key dedup
  - Flush: build_sst_bytes → SstReader::from_bytes → push to sst_readers
  - Compact: MergeIterator over selected SSTables, SstBuilder for output
  - Recovery: SstReader::from_bytes per SST, WAL replay into active Memtable
  - Fixed: large-value write_size uses req.value.len() (not VP size) for flush accounting

  All tests pass:
  - 11 unit tests (sstable bloom, builder, CRC, iterator, existing partition tests)
  - 11 integration tests (f030 flush/recovery, f029 compaction, f031 large values, split/recovery)
