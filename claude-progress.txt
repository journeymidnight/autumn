  Replaced the single-file `writer: Mutex<WriteHalf>` bottleneck in
  autumn-rs/crates/rpc/src/client.rs with an SQ/CQ pipeline:

    SQ (submit side):
      - callers push SubmitMsg { Single | Vectored } onto a bounded
        mpsc::channel (SUBMIT_CHANNEL_CAP = 1024)
      - a single background writer_task owns WriteHalf, drains the rx,
        performs write_all / write_vectored_all sequentially
      - no caller ever holds a write-side mutex; back-pressure comes
        naturally from the bounded channel

    CQ (completion side, unchanged):
      - read_loop task owns ReadHalf, decodes frames, dispatches via
        Rc<RefCell<HashMap<req_id, oneshot::Sender<Frame>>>>

  Critical invariants preserved:
    1. pending.insert(req_id, tx) happens BEFORE submit_tx.send() so the
       CQ can't race in and find no entry.
    2. Borrows of pending are scoped tight (insert/remove then drop guard),
       never held across an await.
    3. submit_tx is cloned from a RefCell borrow (scoped), never held
       across the .send().await — avoids RefCell-across-await panics.
    4. req_id=0 (fire-and-forget) still works: send_oneshot pushes a
       SubmitMsg without inserting into pending.
    5. next_req_id skips 0 on wraparound (reserved for fire-and-forget).

  Public API preserved: connect, from_stream, call, call_vectored,
  call_timeout, call_vectored_timeout, send_frame, send_vectored,
  send_oneshot, peer_addr, pending_count — all signatures identical.

  New tests in client.rs::tests:
    - multiplex_concurrency: 32 concurrent `call` invocations, server
      sleeps inversely to req_id so responses return out-of-order;
      verifies CQ dispatches each response to the right caller.
    - submit_backpressure: constructs a client with SUBMIT_CHANNEL_CAP=4
      and fires 10 concurrent calls against a slow (50ms) server;
      verifies all 10 complete and peak concurrency ≥ 2.
    - send_oneshot_no_response: req_id=0 path, pending_count stays 0.
